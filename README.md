# J의 삶

반복되는 생활 일정과 마감을 기기 안에서 관리하는 Flutter 기반 Local-first 앱입니다. Android 출시를 우선하며 서버, 회원가입, 클라우드 동기화 없이 동작합니다.

## 현재 구현 범위

- 생활 항목 등록·수정·삭제
- 일·주·월·년 반복과 완료 후 다음 예정일 계산
- 월말·윤년 날짜 보정
- 완료 기록과 당시 금액 스냅샷
- SharedPreferences 기반 기기 영구 저장
- 예정일 전 로컬 알림과 Android 알림 권한 요청
- 홈의 오늘·예정·금액·카테고리·최근 완료 카드
- 예정/확정 수입·지출 통계
- 대시보드 카드 표시·숨김·순서 저장
- 기본 빠른 등록 템플릿
- FREE/PRO 및 광고 영역 교체 지점

실제 광고 SDK와 인앱결제 SDK는 연결하지 않았습니다. 백업·복원, 서버 동기화, 계정, OCR과 AI도 MVP 범위에 포함하지 않습니다.

## 실행

```bash
flutter pub get
flutter run
```

정적 분석과 테스트:

```bash
flutter analyze
flutter test
```

Android 실기기에서는 최초 실행 후 우측 상단 알림 버튼을 눌러 권한을 허용합니다. 알림은 정확 알람 권한을 요구하지 않는 `inexactAllowWhileIdle` 방식이므로 제조사 절전 정책에 따라 다소 늦게 표시될 수 있습니다.

## 데이터 보관

항목과 완료 이력은 `shared_preferences`에 JSON으로 저장됩니다. 대시보드 구성도 별도 키에 저장됩니다. 저장 데이터 해석에 실패하면 기존 값을 덮어쓰지 않고 메모리 안전 모드로 시작하며 화면 상단에 경고를 표시합니다.

현재 저장 방식은 소규모 MVP에 맞춘 것입니다. 데이터 규모나 검색 요구가 커지면 저장소 인터페이스 뒤에서 SQLite/Drift 구현으로 교체할 수 있습니다.

## 로컬 알림

- 저장 또는 수정 시 기존 ID의 알림을 갱신합니다.
- 완료한 반복 항목은 새 예정일로 다시 예약합니다.
- 완료한 비반복 항목과 삭제 항목은 알림을 취소합니다.
- 앱 시작 시 저장된 항목의 알림을 다시 동기화합니다.
- 기기 시간대는 `flutter_timezone`으로 확인합니다.

Android 설정에는 재부팅 후 알림 복원을 위한 `RECEIVE_BOOT_COMPLETED`와 플러그인 receiver가 포함돼 있습니다. 정확 알람 권한은 사용하지 않습니다.

## 실기기 확인 목록

1. 알림 권한 허용·거부 시 앱 기능이 계속 동작하는지 확인
2. 항목 등록 후 앱을 완전히 종료하고 다시 열어 데이터가 유지되는지 확인
3. 가까운 미래의 알림을 예약해 수신되는지 확인
4. 반복 항목 완료 후 다음 날짜와 알림이 함께 갱신되는지 확인
5. 비반복 항목 완료 및 삭제 후 예약 알림이 제거되는지 확인
6. 기기 재부팅 후 예약 알림이 유지되는지 확인
7. 날짜·시간대 변경 후 앱 재실행 시 알림이 다시 동기화되는지 확인
8. 큰 글꼴과 작은 화면에서 저장·완료·삭제 버튼이 잘리지 않는지 확인

## 출시 준비 순서

실패 비용을 줄이기 위해 각 단계가 통과된 뒤에만 다음 단계로 진행합니다.

- [ ] 1. 데스크탑의 깨끗한 Git 체크아웃에서 Android 디버그 빌드와 실기기 첫 실행 확인
- [ ] 2. 등록·수정·완료·재실행 후 저장 유지·알림 등 핵심 사용자 흐름 확인
- [ ] 3. 패키지 ID, 앱 이름, 아이콘, 설명과 버전 등 출시 식별 정보 확정
- [ ] 4. 광고 방식 결정 후 실제 광고 SDK 연동 및 실패 시 대체 화면 확인
- [ ] 5. 개인정보처리방침, Android 권한, 데이터 보안과 광고 포함 여부 선언 정리
- [ ] 6. 업로드 키 생성, 릴리스 서명 설정, 서명된 AAB 빌드 및 설치 검증
- [ ] 7. Play Console 등록 자료 작성 후 내부 테스트 트랙 배포 및 최종 점검

현재 릴리스 빌드는 디버그 키를 사용하므로 Play Store 제출용이 아닙니다. 실제 광고 SDK도 아직 연결하지 않았습니다.
